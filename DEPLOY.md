# Deployment Runbook

This is the step-by-step checklist for deploying Nexus JEE. The first deploy has been done; use this as a reference for redeploys, environment changes, or onboarding a contributor.

## Current Live URLs

| Service | URL | Status |
| --- | --- | --- |
| Frontend (Vercel) | `https://nexus-jee-peach.vercel.app` | live |
| Backend (Render)  | `https://nexus-jee-api.onrender.com` | live |
| Health check      | `/api/health` → `{"status":"ok"}` | healthy |

## What Was Done

- Backend deployed to Render via `render.yaml` blueprint (one-click).
- Frontend deployed to Vercel by importing the GitHub repo.
- Production secrets (`JWT_SECRET`, `FERNET_KEY`) auto-generated by Render.
- PWA service worker generated by `vite-plugin-pwa` (192 precached entries).

## One-Time Setup Tasks

### 1. Google Cloud OAuth Client

The OAuth client must whitelist your production domain.

1. Go to [Google Cloud Console → Credentials](https://console.cloud.google.com/apis/credentials).
2. Click your Web OAuth client.
3. **Authorized JavaScript origins** must include:
   ```
   http://localhost:5173
   https://nexus-jee-peach.vercel.app
   ```
4. Save. Changes propagate in ~30s.

### 2. Environment Variables

#### Vercel (frontend) — `nexus-jee` project → Settings → Environment Variables

| Name | Value | Environments |
| --- | --- | --- |
| `VITE_API_URL` | `https://nexus-jee-api.onrender.com` | Production, Preview, Development |
| `VITE_GOOGLE_CLIENT_ID` | `<your-client-id>.apps.googleusercontent.com` | Production, Preview, Development |

**Do not** set `VITE_OPENROUTER_KEY` in Vercel — users bring their own key (encrypted server-side).

#### Render (backend) — `nexus-jee-api` → Environment

| Name | Value | Source |
| --- | --- | --- |
| `JWT_SECRET` | auto-generated | Render |
| `FERNET_KEY` | auto-generated | Render |
| `PYTHON_VERSION` | `3.11.10` | `render.yaml` |
| `DATABASE_PATH` | `/opt/render/project/src/data/nexus_jee.db` | `render.yaml` |
| `FRONTEND_ORIGIN` | `https://nexus-jee-peach.vercel.app` | manual |
| `VITE_GOOGLE_CLIENT_ID` | same as Vercel — **byte-identical** | manual |

> **CORS regex:** `backend/main.py` also accepts the regex `^https://nexus-jee[a-z0-9-]*\.vercel\.app$` so Vercel preview deploys (e.g. `nexus-jee-peach-git-main-*.vercel.app`, `nexus-jee-peach-pr-*.vercel.app`) work without env-var updates. Only the production `FRONTEND_ORIGIN` needs to be set explicitly.

### 3. Render Warmup Cron

Free Render spins down after 15 min idle. Keep it warm:

1. Sign up at [cron-job.org](https://cron-job.org) (free).
2. Create cronjob:
   - **URL**: `https://nexus-jee-api.onrender.com/api/health`
   - **Schedule**: `*/14 * * * *` (every 14 min)
   - **Timeout**: 60s
3. Save. Verify first execution returns 200.

Alternative: [UptimeRobot](https://uptimerobot.com) free tier, 15-min interval.

## Redeployment

### Frontend (Vercel)
- **Auto-deploy on push to `main`**: enabled by default.
- **Manual redeploy**: Vercel → project → Deployments → ⋮ on latest → Redeploy.
- **After env var change**: must manually redeploy (env vars don't apply to already-built bundles).

### Backend (Render)
- **Auto-deploy on push to `main`**: enabled (Render Blueprint).
- **After env var change**: auto-redeploys within ~30s.
- **Manual redeploy**: Render → service → Manual Deploy → Deploy latest commit.

## Verification Checklist

After any deploy or env change, verify in order:

- [ ] `curl https://nexus-jee-api.onrender.com/api/health` → 200 `{"status":"ok"}`
- [ ] `curl -i -H "Origin: https://nexus-jee-peach.vercel.app" https://nexus-jee-api.onrender.com/api/health` → `access-control-allow-origin: https://nexus-jee-peach.vercel.app` in response
- [ ] Open `https://nexus-jee-peach.vercel.app` in incognito → preloader → login page
- [ ] Sign up with a fresh email → redirect to dashboard
- [ ] DevTools → Network shows `POST /api/auth/register` → 200
- [ ] Reload → still logged in (token in `localStorage.nexus_auth_token`)
- [ ] Logout → "Continue with Google" → pick account → login success
- [ ] Render logs free of Python exceptions

## Common Failure Modes

| Symptom | Cause | Fix |
| --- | --- | --- |
| CORS error in console | `FRONTEND_ORIGIN` not set on Render | Add it, save, wait for redeploy |
| "Google Sign-In not configured" | `VITE_GOOGLE_CLIENT_ID` empty on Vercel | Set it, **redeploy** |
| `idpiframe_initialization_failed` | Vercel domain not in Google origins | Add to Authorized JavaScript origins |
| Google 401 "Invalid Google token" | Backend `VITE_GOOGLE_CLIENT_ID` mismatch | Ensure byte-identical values |
| 30-50s first request | Render spin-down | Verify cron ping is running |
| 409 on signup | Email already in use | Use a different email |
| PWA install button missing | `manifest.webmanifest` not served | Check `dist/manifest.webmanifest` exists after build |
| "Disallowed CORS origin" in console | `FRONTEND_ORIGIN` env var on Render is wrong, or a new domain isn't matched by the regex | Update Render env, or extend regex in `backend/main.py` |

## Files of Interest

- `vite.config.js` — PWA manifest, workbox cache, build config
- `render.yaml` — Render blueprint (auto-deploy, env vars, disk)
- `backend/main.py:73` — health endpoint

## Local Development Mirror

```bash
# Frontend
cp .env.example .env       # fill in VITE_GOOGLE_CLIENT_ID
npm install --legacy-peer-deps
npm run dev                # http://localhost:5173

# Backend
cd backend
cp .env.example .env       # fill in JWT_SECRET, FERNET_KEY
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
uvicorn main:app --reload --port 8000
```
